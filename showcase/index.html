More details

  • Synced patterns

    A notice on a synced pattern in the block editor while someone else edits the pattern itself.

  • AI agents

    Labelled in the admin bar, the Active Posts widget and the Editors column, once a plugin such as Agent Users marks them.

  • In the block editor, too

    A plugin that adds real-time collaboration to the block editor can keep its awareness rows in the presence table, so someone editing a post also shows up in the admin bar and the post list. gutenberg-sync-engines has a Presence API backend that does this.

Built for every host

Tracking who is where takes frequent writes, and in post meta or options those writes clear caches across the whole site (#64696). Presence API writes to its own table instead, through the Heartbeat API WordPress already runs.

  • One table

    wp_presence, with a unique key on room and client.

  • 150 seconds

    How long a row counts as present without a fresh heartbeat.

  • Post locks

    _edit_lock lives in the presence table, so refreshing a lock no longer makes cached post queries stale.

  • No extra services

    No object cache, no WebSockets. Anything a host adds is a bonus.

For developers

Learn presence in ten short lessons. PHP functions, REST endpoints, WP-CLI commands, filters and room conventions are documented in the GitHub repository.

// Put this client in a post's room.
wp_set_presence(
	'postType/post:42',
	$client_id,
	array( 'screen' => 'edit' ),
	array( 'user_id' => get_current_user_id() )
);

// Read who is in it.
$entries = wp_get_presence( 'postType/post:42' );
// In a script that depends on wp-presence.
const { users } = wp.presence.usePresenceUsers( room );
